# Rules for Astro pages (`src/pages`)

- **Never write a literal `/case`, `per case`, `/unit` or `per bottle` next to a
  price.** Derive the label from `priceParts(offer.priceDetail)` or
  `offer.priceBasis`. When the basis is unknown, show the amount with no basis.
  (`offers/[slug].astro` `pageTitle`/`pageDesc` currently violate this; fix when in
  the file.)
- Guard every optional field before interpolating: `offer.spec`, `offer.amount`,
  `offer.currency`, `offer.terms`, `offer.tier`, `offer.qty`, `offer.origin`. Omit
  the clause; never render empty brackets or a currency with no number.
- WhatsApp buttons: `enquiryLink(offer, msg)` and `WA_LINK`/`WA_DISPLAY` from
  `src/lib/whatsapp.mjs`. No inline `wa.me` strings. Add `rel="noopener"` on
  `target="_blank"`.
- Slug maps: use `buildSlugMap()`/`buildOfferBySlug()` from `src/lib/slug.mjs`
  instead of copying the loop. Category URL slugs use the same
  `toLowerCase().replace(/\s+/g, '-')` everywhere; if you change one, change all
  (`schema.mjs`, `sitemap.xml.ts`, both dynamic pages).
- Shared helpers (`priceParts`, `STOCK`) belong in `src/lib/`, not duplicated in
  page frontmatter. Move, don't copy.
- Every page sets `<title>`, `<meta name="description">`, and `<link rel="canonical">`
  with the `https://offers.akay.ie/...` absolute URL and a trailing slash.
- JSON-LD goes through `src/lib/schema.mjs`. Don't hand-write schema objects in pages.
- Client-side scripts run on pre-rendered HTML with no data round-trips. Don't
  introduce runtime fetches to Airtable; the token must never reach the browser.
- Copy must be verifiable: the request form uses `mode: 'no-cors'` so it cannot
  know if the request succeeded. Say "request sent", not "we've emailed you".
- `robots.txt`, `sitemap.xml`, `llms.txt` are generated by the `.ts` routes here.
  The copies in `public/` are dead and are not what ships.
- Verify: `npm run build`, then open one file each in `dist/offers/`, `dist/category/`
  and `dist/index.html` and read the price line and the WhatsApp href.
